# GitHub change workflow

Version: 0.2 | Updated: 2026-09-09 | Status: Draft specification

1. Translate the objective into an issue or local work record with acceptance criteria.
2. Read active repository instructions and affected policy.
3. Use feature/, fix/, docs/, agent/, or infrastructure/ branches for reviewable changes once the repository is initialized.
4. Implement the smallest complete change and update affected documentation.
5. Run appropriate checks and record their actual results.
6. Open a pull request with problem, outcome, evidence, and applicable authority.
7. Obtain independent review and required gates.
8. Merge only within explicit authority and repository protections.
9. Link release or follow-up evidence to the work record.

For an empty repository, an authorized foundation commit may initialize the default branch. Do not overwrite newly appeared work or force-push to bypass a conflict.

GitHub write permissions must be proven by the actual operation, not inferred from the account's reported admin status. Record provider failures and pursue authorized recovery.

Proposed controls such as branch protection and CI remain unimplemented until verified. Live publication is authorized by the founder's request to upload the governing documents.
