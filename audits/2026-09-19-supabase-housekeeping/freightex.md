## Additional / bonus findings (outside the numbered checklist)

- **`flight-status-watcher` edge-function auth misconfiguration (likely live bug)**: `supabase/config.toml` has a comment for `[functions.flight-status-watcher]` justifying `verify_jwt=false` ("Private scheduler; handler authenticates x-cron-key before any work"), but **no `verify_jwt` key is actually set** under that header — it falls straight into the next function's block. Per the file's own documented convention, an unset entry defaults to `verify_jwt=true`, which would reject the function's own cron caller (`x-cron-key`, no user session) — the same failure class as a documented historical `customer-api` incident. **Recommend Team Freightex verify this in production immediately** (not just at next house-cleaning pass): add explicit `verify_jwt = false` under `[functions.flight-status-watcher]`.
- Five functions have `verify_jwt` set with no justifying comment (`edi-tender`=true, `fmcsa-lookup`=true, `fmcsa-sweep`=false, `invite-staff`=true, `flight-positions`=true). `fmcsa-sweep=false` uncommented is the most notable (cron/machine sweep per `supabase/migrations/20260816050000_fmcsa_sweep.sql`, plausibly legitimate but undocumented). Recommend a one-line justification comment on each, matching the pattern used everywhere else in this file, plus a CI check that fails on any `[functions.*]` block lacking both a comment and an explicit `verify_jwt`.
