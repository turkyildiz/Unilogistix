# 1. EXECUTIVE SUMMARY

Uni is intended to be an AI-native software company whose primary purpose is to create and operate software businesses.

Uni is not merely a collection of prompts and not merely a coding assistant. It is a proposed operating framework in which specialized AI agents work together under an orchestration layer, using GitHub as the central system of record.

The company should be capable of:

- researching opportunities;
- analyzing markets and competitors;
- creating product requirements;
- designing software;
- writing frontend and backend code;
- testing and reviewing code;
- securing and deploying systems;
- creating documentation;
- creating marketing strategies and content;
- managing social media;
- supporting customers;
- managing sales pipelines;
- tracking orders and operational workflows;
- producing financial and accounting information;
- monitoring business performance;
- identifying risks;
- conducting SWOT analyses;
- proposing improvements;
- launching products;
- operating products after launch; and
- continuously improving its own processes and agent specifications.

The human founder remains the ultimate authority. AI performs delegated work within explicit permissions and approval gates.

The first major product example is intended to be Safe Goes, a GPS-tracking software business. Safe Goes is a product/company operated through Uni; it is not the same thing as Uni.

# 2. COMPANY VISION

## 2.1 Vision Statement

Build a highly capable AI-operated software company that can take a business idea from concept to production and then operate, market, support, measure, and improve that business with a coordinated team of specialized AI agents.

## 2.2 Long-Term Vision

Uni should eventually function like a complete digital company:

**Founder → AI Executive Team → Department Managers → Specialized Agents → Tools and Systems → Products → Customers**

The company should be able to create additional products without rebuilding its organizational infrastructure each time.

## 2.3 Core Objective

Turn software creation from a sequence of disconnected tasks into an integrated company-wide operating system.

# 3. OPERATING PHILOSOPHY

## 3.1 Core Principles

1. Correctness before speed.
2. Automation wherever automation is reliable.
3. Human approval for consequential decisions.
4. Every important action should be auditable.
5. GitHub is a primary source of truth for software and operating documents.
6. Small, reviewable changes are preferred over uncontrolled large changes.
7. Tests are mandatory for production software.
8. Security is designed in, not added afterward.
9. Agents have explicit responsibilities and permissions.
10. Knowledge is version-controlled.
11. Metrics should lead to decisions, not merely reports.
12. Every significant project should produce lessons that improve the organization.
13. Agents should escalate uncertainty instead of pretending to know.
14. No agent should silently override governance.
15. The company should be designed to replace or upgrade individual agents without rebuilding the whole organization.

The founder establishes the mission and retains ultimate authority.

The AI executive layer manages delegated work.

## Approval Model

Recommended categories:

- **Automatic:** low-risk reversible actions.
- **Agent-reviewed:** actions requiring another qualified agent.
- **Executive-reviewed:** high-impact business or technical decisions.
- **Founder-approved:** consequential financial, legal, ownership, security, production, or strategic actions.
